# Sable

A desktop ADE (agentic development environment) for Claude Code and Codex. Web first (Vite + React 19 + TypeScript); a desktop shell comes later. One process serves the UI and hosts the bridge.

## Commands

- `pnpm dev` starts Vite with the bridge attached (WebSocket at `/__sable`). A dev server is usually already running on http://localhost:5173 (or 5174 when that port was taken) — reuse it, never start a second one. `scripts/shot.mjs` finds it by itself.
- `pnpm exec tsc --noEmit -p tsconfig.json` type-checks everything. `pnpm exec vitest run` runs tests.
- Smoke scripts: `pnpm exec tsx scripts/claude-smoke.ts`, `scripts/codex-smoke.ts` (real turns cost the owner's quota: avoid).

## Architecture

- `shared/protocol.ts` is the contract. The bridge owns all state; the UI is a view that calls RPC methods and applies events. Every provider is normalized into one timeline model (`TimelineItem`: user, text, thinking, tool, notice, turn). The UI never branches on provider id except for marks and colour.
- `server/` — bridge. `app.ts` (RPC handlers, sessions, accounts, prewarm), `core/runtime.ts` (SessionRuntime: timeline + prompts + the queue of messages sent mid-turn), `core/cache.ts` (DiskCache: last known sign-in and caps under `~/.sable/cache/`, served at start-up, refreshed in the background), `providers/` (`claude.ts` via the Agent SDK, `codex.ts` via `codex app-server`, `demo.ts` scripted), `services/` (fs, git, terminal, memory).
- Accounts: each agent has the built-in default account plus extras (`AccountInfo`, own config dir under `~/.sable/accounts/`); sessions carry `accountId`, caps are keyed by provider + folder + account (`capsKey`). Capabilities (browser control, computer use, remote control) are `SessionOptions` per session, defaults per agent in settings; live state in `SessionMeta.capState` / `remote`.
- `src/` — UI.
  - `state/store.ts` zustand store (sessions, per-session `data[id]` with `items`, `roots`, `children`, `permissions`, `questions`, `todos`, `caps`), `state/actions.ts` (everything the UI can ask the bridge: use these, do not call `bridge.call` from components unless no action exists, then add one), `state/hooks.ts`.
  - `styles/tokens.css` tokens, `styles/base.css`, `styles/ui.css` primitives (classes), `ui/index.tsx` React primitives (Tip, IconButton, Menu*, Popover*, Modal, Switch, Slider, Segmented, Kbd, Toasts), `icons/index.tsx` (`<Icon name>`, `<Glyph>`, `TOOL_ICON`, `MODE_ICON`), `art/` (LogoMark, ProviderMark, Tiles loader, DitherField, and `<Backdrop surface>`: the configured backdrop for home, session, onboarding and the Settings preview; its config is `AppSettings.backdropConfig`, with the default, presets and `normalizeBackdrop` in `shared/backdrop.ts` and uploaded images behind `backdrop.*` in `server/services/backdrop.ts`).
  - `features/<area>/` one folder per area with its own CSS file imported by its component (`onboarding/` first-run welcome, `connect/` sign-in and account cards, `composer/` incl. `QueueStrip`, `rail/` side panel incl. the Browser tab). `app/Capabilities.tsx` the top bar's capability switches. `components/` shared view pieces (Markdown, CodeBlock, DiffView).
  - `lib/models.ts` how models are named and which ones the model menu lists (`modelName`, `modelNameById`, `visibleModels`): never show an alias name or a raw model id in the UI.
- Dev helper in the browser console: `sable.demo('refactor the session module')` opens a Demo session and sends a prompt (keywords pick scenarios, see `server/providers/demo-scenarios.ts`: refactor, plan, question, agent, search, markdown, error, mcp, long, hi; `/compact`, `/context`). `sable.store.getState()`, `sable.actions`.

## Working rules

- Stay inside the files you were given. Shared files (`shared/`, `src/state`, `src/styles`, `src/ui`, `src/icons`, `src/art`, `src/app`) belong to the lead: add to them only when the brief says so; otherwise report what you need.
- This is a laptop that must stay responsive: no parallel heavy processes, no extra dev servers, kill what you start, no new dependencies without a strong reason (say so in your report).
- Verify visually with headless screenshots, not the Browser pane (it does not render while the display is off): `node scripts/shot.mjs --size 1280x800 --eval "<js>" --wait 1500 --shot scratch/<name>.png` (steps run in order: `--eval`, `--wait`, `--click "css"`, `--hover`, `--fill "css=>text"`, `--type`, `--key`, `--shot file[@css]`; see the header of that file), then Read the PNG. Each run starts on the home screen with a clean profile; open a session with `--eval "sable.actions.openSession(id)"` or start one with `--eval "await sable.demo('refactor the session module', {mode:'bypassPermissions'})"`. Page errors and console errors are printed by the script. One headless run at a time, write images only to `scratch/` (git-ignored), and look at your screenshots critically: spacing, alignment, hierarchy, states. Type-check before you finish.
- Real provider turns cost quota. Build and test against the Demo provider.

## Design language (read this twice)

The brief from the owner: far better looking than Claude Code's own app; modern, simple, clean; dark, calm panels over a rich backdrop; subtle background effects; colourful dither; rich detailed icons; beautiful motion; cinematic. He rejected the earlier tactile look (lit edges, gradient fills, bevels) as cheap: controls are quiet, flat and precise, premium through proportion, spacing and type. Explicitly forbidden: monospace uppercase labels, "eyebrow" kickers above headings, sloppy colours, generic AI-app look.

Newer guidance from the owner: really clean and professional. No descriptions in pickers and menus (expect people to know), no helper sentence that restates a label, no decorative colour on controls, no tags or badges that do not carry needed information, nothing extra on the home screen.

- Monochrome: ink surfaces, ivory text. Surfaces are neutral near-black (`--bg` ground, `--sheet` stage, `--panel`/`-2`/`-3` each one step lighter, `--fill-*` for hover/selected, `--hl` for a highlighted row, hairlines `--line*`). Colour lives only in the backdrop (the dither field) and the agent marks, plus tiny meaningful marks: `--amber` waiting on you, `--red` error, green/red numbers in diffs. `--accent` is neutral ivory. No tinted icons or tiles, no coloured chips or buttons, never a hue as decoration, never new colours: use tokens.
- Depth: ink and light, not bevels. Surfaces are flat; depth comes from layering (each layer one small step lighter) and from light that reacts. Reactive hairlines: borders are almost invisible at rest and brighten near the pointer on any element with `data-spot` (cards, panels, menus, dialogs, the composer; `ui/spot.ts` runs the one listener, the ring is the element's `::before`, so never write your own pointer listeners or use `::before` on a spot surface). Floating glass (`.pop`, `.dialog`, `.glass`, toasts) is flat frosted ink with a faint static grain (`--grain`) and one soft shadow (`--shadow-pop`). Small accents use monochrome dither, never gradients: `.dither-sel` on a selected row's pill, `.meter` + `.meter-fill` (`--p`, `data-level`) for progress, `.skel` for skeletons. Controls: `.btn` is one fill step with an almost invisible hairline, hover one step lighter, press `scale: .97`; one solid ivory `.btn-primary` per view; fields are a darker well whose hairline turns soft ivory on focus (`--focus-field`); the focus ring is ivory at reduced strength (`--focus`). Send is a solid ivory disc with a dark arrow, stop an ivory disc with a dark square, both static. Nothing glossy anywhere.
- Type: Inter (variable, optical sizes; `--font-sans`) for the interface; Geist Mono (`--font-mono`) only for code, diffs, terminal output and inline code. Paths, folder names and commands shown as labels use the UI font with the directory dim and the name regular (`<PathLabel path>`, `.path`), never mono. 13px UI, sentence case everywhere, no uppercase or letter-spaced labels. Use the scale (`--t-*`) and weights (`--w-*`: 400/500/580); headings are 600 and tight (`.h1/.h2/.h3/.display`); figures that line up use `.num` (tabular). Small secondary text is `--text-2`/`--text-3`, never below 11.5px.
- Shape: radii from tokens (`--r-sm` 8 controls, `--r-md` 10, `--r-lg` 12 cards/menus, `--r-xl` 14 panels, 16 menus, 20 the composer). Controls are 30px tall with 13px text (`--t-ui`), composer toolbar controls 28px and fully round, menu rows 26 to 28px. Calm rhythm, a single column (`--column`) for reading.
- Icons: plain line icons, monochrome. `<Icon name>` (Phosphor regular; bold for tiny carets and checks) inline; `<Glyph name>` is the same plain icon in a fixed box for rows that need alignment (its `tone` only applies when it is amber or red). Icons answer their control on hover with one small move (icons.css). Never emoji. Add missing icons to `icons/index.tsx` using the per-icon Phosphor import pattern there.
- Motion: purposeful, fast, soft. Enter with a short rise + fade (never a blur filter), spring for things that move (`motion/react`, stiffness 380–520, damping 32–40), `--ease-out` for CSS. Durations from tokens (`--d-1..4`). Animate height when revealing details. Nothing bounces wildly, nothing loops except the working indicator (`<Tiles>`), `.shimmer` text and the dither field. Respect `prefers-reduced-motion`.
- Effects: the spectacle lives in the backdrop and at a few moments, never on controls. The field answers the app with one-shot beats (`fieldBeat(kind, el)` in `art/events.ts`, drawn in the worker, `FieldBeat` in `art/field.ts`): `send` (a pressure wave from the send key: thin crest that bends the pattern, a trough, an echo), `done` (a ring closes in on the composer as the turn's steps gather, then the band exhales), `fail` (the light dips and recovers), `pulse` (a softer wave for small moments). While a turn runs the field drifts quicker; waiting on you it stills (amber band). Strength follows the surface (full on home, restrained in a session, nothing when the backdrop is off, still or under reduced motion) and the backdrop's own amount, speed and reaction settings; no new switches. The pointer leaves a faint light that trails it on full stages. Rest: after 20 s with no input and no running turn the field eases to a still frame and stops drawing (no timer, no frame) until input or a beat wakes it. View changes use the dither veil (`veil(host, 'swap' | 'reveal' | 'cover')` in `art/veil.ts`): four quarter-tiles of the 4x4 ordered dither in the surface colour, stepped by opacity only, so content dissolves into the ground and resolves out of it (sparse, checker, solid, as the mark builds) on the compositor; 260 ms for a swap, the views only change opacity and transform, nothing reflows. Home arrives as one movement (the launch mark glides into place or builds in dither order, then headline, then composer); the mark glints a missing corner cell per keystroke. Rules: every effect is one-shot and a few hundred ms (the field, `<Tiles>` and `.shimmer` are the only loops); colour only in the field and the agent marks; transform, opacity and worker canvas only (no `filter`, no animated `box-shadow`, no `mask-image` on live content); zero cost at rest; under load the governor sheds the effects (bending, echo, pointer light) before it lowers the frame rate. A moment that is not clearly better than nothing is removed.
- Density: quiet by default, detail on demand. Rows are one line until expanded. Secondary actions appear on hover/focus. Empty states are one calm sentence, no illustrations.
- Copy: plain, specific, short. Say what happens ("Allow once", "Rewind to here"), no exclamation marks, no filler, no em dashes, no marketing voice.
- Every interactive element needs hover, active and focus-visible states, an accessible name, and keyboard access. Show shortcuts with `<Kbd combo="mod+k">`.
- Performance is part of the design: streaming must never re-render settled items; subscribe narrowly to the store (`useStore(s => s.data[id]?.items[itemId])`), memoize, avoid layout thrash, keep animations on transform/opacity. `backdrop-filter` only on small floating layers and the home composer; no `mask-image` on scrollers or animated content (use a gradient overlay pseudo-element in the surface colour); no `filter` in animations or at rest; hover/press transitions on background-color, color, opacity or transform only, 80 to 120ms, never on box-shadow, border or size; menus open in about 120ms; `will-change` only while something animates.
